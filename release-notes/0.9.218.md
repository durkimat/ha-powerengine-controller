### Behaviour changes

- **The one-button update and the watchdog are part of the integration; the package file is gone.** Earlier versions
  wrote `powerengine_handover.yaml` into your `packages` folder (a `script.powerengine_update` and a "PowerEngine -
  Watchdog" automation, with your inverter's entity names written into it) and needed `homeassistant: packages:` in
  `configuration.yaml`. Now:
  - **`powerengine.update`** (a service the card's **Update** button calls) asks HACS for the latest release, installs
    it, waits for the engine to restart onto it and leaves a notification saying what happened.
  - **The watchdog** is run by the integration. The engine tells it, ahead of time and whenever it changes, what to do
    to *your* inverter (the service calls that close its windows and set Self-Use or switch remote control Off, built
    from the same entities the engine drives) and whether PowerEngine is in control. If the engine's heartbeat stops for
    15 minutes while it is, the integration makes those calls and notifies you. It keeps what it was told, so it still
    works if Home Assistant restarts while the engine is down. (The old automation read the engine's own sensor to
    decide whether to act, which is unavailable exactly when the engine is down.)
  - **The old package file is removed by PowerEngine itself**, once the integration has confirmed it holds the watchdog,
    with a backup beside it (`powerengine_handover.yaml.bak-<date>`), and Home Assistant is told to reload scripts and
    automations so the old watchdog stops. A file of that name that PowerEngine did not write is left alone and
    reported in the log.
  - **After updating to this release, restart Home Assistant once.** The new engine starts at once, but the integration's
    part (the watchdog and the update service) loads at the restart; until then the old package, and its watchdog, stay
    in place, so there is no gap. The card's Update button uses the old script until the restart, then the service.
- **The Home Assistant package banner and notices are gone** from the Config page and the setup card (there is no package
  to load), and the diagnostic sensor `sensor.pe_diag_package` is removed.
- The install guide no longer asks for a `packages` folder, and its "update the card too" advice (stale since the card
  joined the integration) is removed.

### Behind the scenes

- New request `failsafe` in the engine/integration protocol (`pe_core/protocol.py`): data, not code. An integration that
  does not know it answers with an error and the engine keeps its other arrangements and asks again every two minutes.
- `pe_core/failsafe.py` builds the calls from the inverter adapter; `custom_components/powerengine/watchdog.py` and
  `updater.py` are the integration's side; `pe_core/hapackage.py` now only retires the old file.
- Tests: the failsafe's content and hand-over (`tests/test_failsafe.py`), retiring the package (`tests/test_hapackage.py`),
  the request over a real socket and replayed after a reconnection (`tests/test_host_socket.py`), the watchdog (quiet
  engine, alive, not in control, nothing to do, once per silence, acts again after a return, one call failing, survives a
  restart) and the update service (`integration/tests/test_watchdog.py`), and the card's use of the service
  (`card/tests/update_service.test.cjs`).
