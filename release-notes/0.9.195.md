### Behaviour changes

- **Notifications and announcements are now channels and rules.** A channel is a place a message can go (Home Assistant's notification area, a phone, the Alexa speakers, WhatsApp) with its own opening words, hours and test; the rules say which kinds of message go to which channels, so one message can go to several places. Your existing settings (`service`, `events`, `alexa`) still load and become the same channels and rules, so nothing changes until the Config page saves. See docs/SITE.md.
- **A message outside a channel's hours can be held.** It is sent when the hours open, marked as a held message ("Held message from 10:30 pm yesterday."), one per channel each time round, and dropped if it is no longer worth sending (a reminder once the event has started). The other choice is to skip it. Grid event reminders used to be skipped outside the allowed hours; they are now held for the Alexa and WhatsApp channels unless the channel says skip.
- **Other things in Home Assistant can send through the same rules.** Fire the event `pe_notify` with a `kind` and some `text` (docs/SITE.md). A kind seen for the first time is listed on the Config page so it can be routed. Limited to 30 a day.
- **`sensor.pe_ui_notify`** carries the channels, rules, kinds, held messages and the last deliveries for the Config page. The Config page's channel test uses the event `pe_notify_test`. Needs card 0.9.195 for the new Notifications section.

### Behind the scenes

- `pe_core/router.py` (kinds, rules, hours, the held-message outbox) replaces the notification calls in `powerengine.py`; `config.py` parses channels and rules and converts the older settings. `pe_alexa_test` still works for older cards.
