### Behaviour changes

None. This release only renames things inside the engine; nothing PowerEngine does changes.

### Behind the scenes

- **The engine's host calls have neutral names.** The scheduling and listening calls were AppDaemon's (`run_in`, `run_every`,
  `run_daily`, `cancel_timer`, `listen_state`, `listen_event`, `cancel_listen_state`, `cancel_listen_event`); they are now
  `call_later`, `call_every`, `call_daily`, `cancel_call`, `on_state`, `on_event`, `off_state` and `off_event`, in the host
  protocol (`pe_core/host.py`), the three hosts (`host_socket.py`, `host_local.py`, the comparison harness), the scheduler, the
  engine and the tests. The other host calls (`get_state`, `get_history`, `render_template`, `get_timezone`, `call_service`,
  `fire_event`) are plain Home Assistant vocabulary and keep their names. A state callback still takes `(entity, attribute,
  old, new, kwargs)`, an event callback `(event, data, kwargs)` and a timer callback `(kwargs)`; `pe_core/host.py` says so.
- **The tests no longer talk about AppDaemon.** Their fakes are "a fake host" and "a stub host", their names and docstrings
  say what they check (the engine reaches Home Assistant only through the host, a restart of the engine, and so on), the
  list of AppDaemon-only names the engine was forbidden to use is gone, and so is the comparison tests' check that nothing
  imports `appdaemon`. The one mention left is the header text of the old package file, which is what lets PowerEngine
  recognise and remove it.
