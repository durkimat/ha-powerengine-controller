### Behaviour changes

- **The dashboard cards showed "Configuration error" on a phone using Home Assistant Cloud.** Since 0.9.215 the card was
  added to Home Assistant's pages as a background module, which the dashboard does not wait for: on a fast connection
  the card arrived in time, on a slow one (mobile data through the cloud) the dashboard was drawn first and every
  PowerEngine card stayed in error. The integration now adds the card to Lovelace's resources itself, which the dashboard
  does wait for (the page-wide module remains only where resources are kept in YAML). The resource is kept at the card's
  current address on every update, the old entry is replaced rather than duplicated, and nothing else in the list is
  touched. Nothing to do: if the card was added by hand, the entry for the same address is adopted.
- **The card file is now cached by the phone or browser** (it was fetched in full, about 600 KB, on every page load). Its
  address changes whenever PowerEngine is updated, so a new card is still fetched at once.
- **Health page: the smart-charge slots table raised a template error** for a slot EDF had replaced (status
  `superseded`, since 0.9.178), and so showed an error in the card. Such slots are listed as "replaced", and any status the
  table does not know is now shown as it is instead of failing.

### Behind the scenes

- `integration/tests/test_frontend.py` covers the resource (created once, moved when the file changes, duplicates tidied,
  removed on unload, other resources untouched) and the cache header; `tests/test_dashboard.py` renders the slot table
  with every status the slot tracker can write.
- The manifest lists Lovelace as an after-dependency so its resource list exists when the card is added.
