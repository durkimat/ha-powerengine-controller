### Behaviour changes

- **A second replay says whether the forecast was the problem.** Each nightly comparison now also replays engine v2 with the day's real sun and real house use as its forecast. The "why" of a day adds a line: either that v2 would have done about the same (so the forecast was not the problem) or how much more or less it would have saved. The extra replay adds a few minutes to each night's run; if it fails, the rest of the comparison is still kept. Days compared before tonight don't have it until they are compared again.
- **Compare a day again.** In Engines compared an administrator sees "Compare this day again" in an opened day and "Try again" on a skipped day. It queues that finished day (from the last week, with a forecast record) in the same background runner; the table updates when it finishes (about 15 minutes), and the card says if it could not be started.

### Behind the scenes

- `compare/whatif.py` (the real-sun scenario: the pack's forecast set to the actual solar, the snapshot's Solcast figures left out, a house profile of the day's real use); `Scheduler.recheck` and `forced`; the `pe_compare_recheck` event and its `pe_compare_recheck_result` answer; `run --no-what-if`. Needs card 0.9.188.
