### Behaviour changes

None for what PowerEngine does with the battery. What the Config page suggests and recognises is the same as before (it is
checked against a record of what it was), and one new diagnostic sensor appears.

- **New diagnostic sensor `sensor.pe_diag_control_entities`** ("Inverter control entities"): which of the inverter's control
  entities the engine drives (the remote-control ones by role, and every window, current, update-button and mode entity).
  The card's **Tests** page and the **diagnostics export** read it instead of guessing Solis entity names; with it the card
  contains no inverter or integration names at all.

### Behind the scenes

- **No entity names and no integration names in the code.** The entity patterns PowerEngine uses to pre-fill the Config
  page and to recognise an integration in the wizard were Python (`roles.py`: 30 roles; `adapters/detect.py`) and card
  JavaScript. They are data now, one file per integration in `engine/pe_core/adapters/integrations/` (`edf`, `octopus`,
  `zappi`, `solcast`, `axle`; the Solis inverter's were already in `devices/solis.yaml`). `adapters/integration_data.py`
  loads and checks them (an unknown part, a bad pattern or an unknown role is refused, naming the file); `roles.py` merges
  them in. `tests/test_integration_data.py` proves the merged suggestions and the detection table are identical to what the
  code had (a recorded copy, `tests/golden/suggestions_and_detection.json`) and that no entity pattern or integration name is
  left in `roles.py`, `detect.py` or the card. Adding an integration is adding a file (`docs/INVERTERS.md`).
- The first solar plant's suggested entities (`plant_suggest:` in the inverter's definition) are published with the role
  catalogue; the card no longer has them built in.
- The two release-script stand-ins added for 0.9.221 are gone (the `apps/powerengine` symlink and the fallback in
  `prepare_release.sh`).
- Tests: the card's Tests-page finder and the diagnostics filter work from the published list; the engine's publication of
  it is tested (`tests/test_failsafe.py`).
