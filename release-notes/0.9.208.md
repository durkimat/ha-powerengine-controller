### Behaviour changes

- **PowerEngine can now be installed as a Home Assistant integration** (HACS category Integration; see
  `docs/INTEGRATION.md`). The engine runs as its own process that the integration starts and watches, so updating
  PowerEngine restarts only the engine, not Home Assistant. No AppDaemon, no `apps.yaml` and no MQTT broker are needed:
  the entities are real Home Assistant entities with the same ids as before (`sensor.pe_...`), the engine keeps its
  settings and data in `/config/powerengine`, and the card and Config page work unchanged.
- **The AppDaemon app is unchanged and still supported.** Nothing changes for an existing AppDaemon install.
- **Moving from the AppDaemon app** is a service, `powerengine.migrate_from_mqtt`: it saves a snapshot of the app's
  entities, clears their MQTT messages and removes them, and the engine then makes the same entities natively, so
  history carries on. The engine does not start while the app is running or while its entities are still registered.
- A **Shadow** mode runs a second engine beside a live one on a copy of its data, with its own `sensor.pe_shadow_...`
  entities, sending nothing: for comparing a change before trusting it.

### Behind the scenes

- `custom_components/powerengine/` (the integration; its `engine/` folder, the two protocol files and the manifest
  version are generated by `tools/build_integration.py`, kept current by the release tools and checked in CI);
  `docs/plans/native-integration.md` and `docs/plans/cut-over.md` have the design and the runbook.
- CI validates the repository for HACS as both an integration and an AppDaemon app, and runs the integration's tests
  against a real Home Assistant (`integration/`).
