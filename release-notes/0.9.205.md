### Behaviour changes

- Remote-control commands to the inverter are now sent from a worker thread, so the app no longer stands still while it
  waits for the inverter. Each command is three calls through the SolaX Modbus integration, and on a slow day each took
  2 to 4 seconds, which held up everything else the app does (the heartbeat, the 30-second cycle, the card's buttons) for
  up to 15 seconds and made AppDaemon warn "Excessive time spent in callback". The calls are the same, in the same order,
  one command at a time; nothing else is sent while one is on its way, and Off and the 5-second re-send join the same
  line, so nothing can overtake a command. The log line "RAM remote control: Force charge at 5000 W", the write
  journal and the daily counts are made when the writes have landed, as before. A command that has not landed after 60
  seconds is given up on and sent afresh.
- Nothing changes in demo mode or for timed windows.

### Behind the scenes

- `pe_core/background.py` is the worker; hosts say whether to use it (`background_writes`): AppDaemon does, the fake the
  tests use does not, so every existing test still sends in step. New tests (`tests/test_ram_background.py`) use an
  inverter that is slow to answer.
